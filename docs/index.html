AI writes code faster than ever — but we’re left wondering what it broke. Samurai Agent is a guardrail for AI-generated code inside your IDE.

How it works

1

You write code with your AI coding tools (e.g. Cursor or Claude Code)

Samurai Agent automatically detects AI edits.

2

Samurai Agent calculates regression risk and shows a warning in your IDE.

It uses JavaScript/TypeScript-specific bug data, so detection is fast and lightweight.

3

Start a code review with one click.

Samurai Agent reviews the change using JS/TS bug data and runtime signals to catch regression bugs.

Samurai doesn’t replace your AI coding agent — it reviews AI-generated code to catch regressions before you ship.

What makes Samurai fundamentally different?

Samurai moves code review from PR-time to edit-time — and uses the AI's plan + JS/TS bug patterns to catch real regressions.

Edit-time review (not PR-time)

Traditional tools review after commit or pull request. Samurai reviews immediately after each AI edit — before context is lost and regressions spread.

  • Runs right after AI edits
  • No PR delay
  • Immediate feedback in your IDE

Plan-aware + JS/TS regression-aware

Because Samurai runs inside your IDE, it can use the AI's planning context and real JS/TS bug patterns to flag subtle logic conflicts — not generic LLM advice.

  • Uses AI plan + conversation context
  • JS/TS-specific bug patterns
  • Focused regression warnings

Architecture for contributors

The pipeline is layered. Each stage below names what happens, whether a model is called, and where the code lives.

1. Edit-time detection (no LLM)

EditBurstTracker watches the editor and the filesystem (CLI tools write straight to disk). RegressionRiskScorer scores the diff with JS/TS patterns, paths, and scope — no model call. RegressionNotificationService shows the IDE warning. Files: src/services/EditBurstTracker.ts, RegressionRiskScorer.ts, RegressionNotificationService.ts.

flowchart LR edit[AI edit] --> burst[EditBurstTracker] burst --> score[RegressionRiskScorer] score --> banner[IDE warning]

2. Context the review receives

The review starts with the diff, the risk signals, and plan files from Cursor, Claude Code, Windsurf, or Antigravity (AIToolPlanDiscovery).

3. The review loop

PlanningAgent.execute repeats until a final report or timeout: thought, tool calls, or final response. RuleSelector picks prompts; ToolRegistry runs tools. Files: src/agent/core/PlanningAgent.ts, RuleSelector.ts, src/agent/tools/.

flowchart TD start[PlanningAgent.execute] --> think[Model: thought / tools / final] think -->|tools| registry[ToolRegistry] registry --> think think -->|final_response| report[Review report] think -->|timeout| partial[Partial report]

4. Tools the agent can call

Search the codebase, read git diff/history, LSP diagnostics, static analysis, graph context, sandboxed file reads, and Node runtime inspection. Original project files are never modified. Engine tools live under src/agent/tools/engine/.

5. Debugging path (separate from regression review)

Epicenter search, hypothesis generation, runtime analysis, and the root-cause report live under src/agent/tools/debugging/ and src/agent/prompts/debugging/. This is why the tree looks large — keep it mentally separate from the edit-time review path.

6. Model call (bring your own key)

LLMProviderService uses the active user entry: provider, typed model name, and API key from VS Code Secret Storage. No built-in catalog, no proxy, no sponsored tier. Files: src/agent/llm/, src/common/utils/llmSecretStore.ts.

7. Where to change it

  • JS/TS risk pattern → src/services/RegressionRiskScorer.ts and src/agent/tools/analysis/
  • Review prompt or rule → src/agent/core/RuleSelector.ts and src/agent/prompts/
  • New provider protocol → client in src/agent/llm/ plus the add-model form (model names are not listed in the repo)
flowchart TB ext[src/extension.ts] --> services[src/services] ext --> agent[src/agent/core] agent --> tools[src/agent/tools] agent --> prompts[src/agent/prompts] agent --> llm[src/agent/llm] ext --> webview[src/webview]
